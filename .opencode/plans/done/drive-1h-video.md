# Plan: Comprendre pourquoi une vidéo d'1 h hébergée sur Google Drive n'est jamais résumée

> Constat de l'exploration (Plan agent, lecture seule) :
> - **Installation** : le projet est une extension Chrome MV3 (Vite + Preact + ffmpeg.wasm), pas un binaire. Sur ce poste : Node v20.20.2 / npm OK (`.nvmrc`=20), `node_modules` présent, `npx tsc --noEmit` OK, `npx vitest run` = 77/77 verts, `dist/` construit le 29/09 (v0.2.0, `dist/ffmpeg/ffmpeg-core.{js,wasm}` présents). **Aucun navigateur Chromium « classique » détecté** (seul `google-chrome-for-testing` existe, sans doute celui de Playwright) : impossible de savoir d'ici si/où `dist/` est chargé en « Load unpacked ». `ffmpeg`/`yt-dlp` système absents (non requis : ffmpeg.wasm est embarqué).
> - **Pistes probables (à confirmer)** :
>   1. *Détection* : `content_scripts.all_frames=false` et `providerFromUrl` ne connaît que YouTube/Vimeo. Un lecteur Drive (`drive.google.com/file/d/ID/view|preview`) charge sa `<video>` dans une iframe cross-origin (`youtube.googleapis.com/embed/...`) que le content script ne voit pas → pas de `mediaSrc`.
>   2. *Capture réseau* : `classifyMedia` (`src/transcription/media.ts`) ne reconnaît que `.m3u8/.mpd/.mp4/.ts/.m4s/segment/vimeocdn`. Les flux Drive sont des `googlevideo.com/videoplayback?...&range=...&mime=video%2Fmp4` → classés `unknown` → jamais enregistrés par `media-capture.ts` → `MEDIA_NEEDS_PLAYBACK` / `MEDIA_NOT_CAPTURABLE` après 5 s d'attente. De plus chaque requête `videoplayback` n'est qu'une plage d'octets, pas le fichier.
>   3. *Passage à l'échelle d'1 h* (même si la capture marchait) : tout le média est téléchargé en mémoire (`downloadSource` → `concat`), puis ffmpeg.wasm mono-thread (limite ~2 Go, lent) ; MP3 64 kbps ≈ 29 Mo → `planChunks` (24 Mo) = 2 morceaux, base64 ≈ 16-32 Mo par requête OpenRouter sans `max_tokens` ni retry ; timeout global de 15 min (`timeoutSeconds`) qui couvre téléchargement + décodage + transcription ; état des jobs uniquement en mémoire du service worker MV3 (peut être tué → popup « tourne » sans résultat).
>   4. Le message d'erreur technique existe déjà (`diag` : `sample=…`, `kinds=…`) et s'affiche dans le popup (`detail`) : c'est la source de vérité à récupérer.
